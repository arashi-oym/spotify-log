# 🎧 My Listening Log

Spotifyで聴いた曲を自動で記録して、Apple Musicの「Replay」のようなランキングや分析を、自分専用のページで見られるしくみです。

**スマホだけで作れます**（iPhone・Androidどちらでも。パソコンがあればパソコンでもOK）。費用はかかりません。

**必要なもの**
- **Spotify Premium** の契約（Spotifyの決まりで、Premiumでないと再生履歴を読み取れません）
- **GitHub** のアカウント（無料。記録の保存と、専用ページの公開に使います）
- 30分ほどの時間（はじめての設定のときだけ）

## はじめての設定（スマホだけでOK）

**スマホで作業するときのコツ**
GitHubは、スマホ表示だと一部のボタン（「Settings」など）が出ません。ブラウザのメニューから **「PC版サイトを表示」**（Safariは「ぁあ」→「デスクトップ用Webサイトを表示」、Chromeは「︙」→「PC版サイト」）に切り替えて作業してください。

### 1. GitHubに自分用のコピーを作る

1. [GitHub](https://github.com/signup) のアカウントを作る（持っていれば不要）
2. このツールを教えてくれた人から受け取った **テンプレートのURL** を開く
3. 緑の **「Use this template」** →「**Create a new repository**」
4. 「Repository name」に好きな名前を入れる（例：`listening-log`）
5. **Public** を選んで（Privateだと無料ではページを公開できません）、「**Create repository**」

### 2. ページの公開設定をする

1. いま作ったリポジトリの「**Settings**」→ 左メニュー「**Pages**」
2. 「Build and deployment」の「**Source**」を **「GitHub Actions」** に変更

### 3. 最初の実行をする

1. リポジトリ上部の「**Actions**」を開く
   - 「I understand my workflows, go ahead and enable them」という緑のボタンが出たら押す
2. 左の「**Spotify再生記録**」→ 右の「**Run workflow**」→ 緑の「**Run workflow**」
3. 1〜2分待って、「record」と「deploy」が緑のチェック ✅ になればOK
4. 「Settings」→「Pages」に表示される **「Your site is live at …」のURL** があなたの専用ページです。開いてみてください

ページの上に「**ようこそ！あと少しで記録が始まります**」と出ていれば、ここまでは成功です。

### 4. Spotifyで「アプリ」を作る

ここで作る「アプリ」は、あなたの再生履歴を読み取るための**自分専用の通行証**のようなものです。アプリストアに出すものではありません。

1. 専用ページの「**Spotifyと連携する**」ボタンを押す（連携ページが開きます）
2. 連携ページの「手順1」に出ている **URL をコピー**
3. [Spotify for Developers](https://developer.spotify.com/dashboard) をPC版表示で開き、Spotifyのアカウントでログイン（初回は利用規約への同意や、メールアドレスの確認を求められます）
4. 「**Create app**」を押して、次のように入力
   - App name：好きな名前（例：`My Listening Log`）
   - App description：好きな説明（例：`自分の再生履歴の記録用`）
   - Redirect URIs：さっきコピーしたURLを貼り付けて「**Add**」
   - 「Which API/SDKs are you planning to use?」：**Web API** にチェック
   - 規約に同意して「**Save**」
5. 作ったアプリの「**Settings**」を開き、**Client ID** と、「View client secret」で表示される **Client Secret** を確認（あとでコピーします）

### 5. GitHubに Client ID と Client Secret を登録する

1. GitHubのリポジトリの「**Settings**」→「**Secrets and variables**」→「**Actions**」
2. 「**New repository secret**」で、次の2つを登録（名前は大文字・アンダーバーまで正確に）

| Name | Secret（入れる値） |
|---|---|
| `SPOTIFY_CLIENT_ID` | SpotifyのClient ID |
| `SPOTIFY_CLIENT_SECRET` | SpotifyのClient Secret |

### 6. Spotifyと連携する

1. 連携ページに戻り、「手順2」に Client ID と Client Secret を入力
2. 「**Spotifyと連携する**」→ Spotifyの画面で「**同意する**」
3. 連携ページに戻ってきて、**リフレッシュトークン**（連携のカギ）が表示されます
4. 「トークンをコピー」→「**GitHubで新しく登録する**」
5. Name に `SPOTIFY_REFRESH_TOKEN`、Secret に貼り付けて「**Add secret**」

### 7. 完成

1. 「Actions」→「Spotify再生記録」→「**Run workflow**」
2. 緑のチェックになったら、専用ページを再読み込み

最近聴いた曲（直近50曲）が表示されていれば完成です。ここから先は、**1時間ごとに自動で記録が増えていきます**。

**ホーム画面に置くと便利です**
- iPhone：Safariで専用ページを開く →「共有」→「ホーム画面に追加」
- Android：Chromeで専用ページを開く →「︙」→「ホーム画面に追加」

**もっと過去の記録も見たいとき**
自動の記録は、設定した日以降の分だけです。それより前の分は、Spotifyに再生履歴を請求して取り込めます → [過去の再生履歴を取り込む](#過去の再生履歴を取り込む)

## ふだんの使い方

**専用ページを開くだけです。** 操作は何もいりません。

- 1時間ごとに自動でSpotifyの再生履歴を確認して、ページを最新にします。スマホやパソコンの電源が切れていても動きます
- 聴いてからページに反映されるまで、最大1時間ほどかかります
- 表示が古いときは、ページを再読み込みしてください（スマホは画面を下に引っ張る）

**この説明書を見る**
専用ページの「記録の状態」にある **「説明書・ダウンロード」** を押して開き、**「使い方・直し方を見る」** を押すと、いつでもこの説明書を開けます。

**期間の切り替え**
上のボタンで「7日間」「30日間」「今月」「今年」「全期間」を切り替えられます。
「期間を選ぶ」からは、好きな月・好きな年・好きな日付の範囲を選べます。「日付で指定」を開くと、開始日は今日の14日前、終了日は今日の日付が自動で入ります（それぞれ「今日」ボタンでいつでも今日に戻せます）。

**曲・アーティスト**
ランキングの右上の切り替えで、「曲」と「アーティスト」のランキングを見られます。

**詳しく見る（タップで開く）**
- ランキングの曲・アーティストを押すと、**詳細画面**が開きます。いつどれくらい聴いたかのグラフ（日・週・月・年で切り替え）、曲の旬、年表などを見られます。アーティストの詳細では、そのアーティストの中での曲ランキングも見られます
- サマリーの緑の「**再生回数**」を押すと、すべての再生の推移と、よく聴いた日・月のランキングが見られます
- サマリーの「**聴いた曲**」「**アーティスト**」を押すと、分析タブの「新しい出会い」に移動します

**検索**
右上の🔍ボタンから、曲名・アーティスト名で探せます。ランキングに出てこない曲も見つけられます。

**分析タブ**
ページ上部の「🏆 ランキング｜📊 分析」で切り替えます。上部で選んだ期間で集計します。
- **記録**：連続記録、最長リピート、いちばん聴いた日・月 など
- **聴き方のくせ**：リスナータイプ、曜日×時間帯のヒートマップ、リピート度
- **あなたの音楽年表**：記念の再生、推しの交代、毎年のトップ など（全期間）
- **1年前の今日**：今日と同じ日付の、1年前・2年前…に聴いていた曲
- **アーティストの順位の移り変わり**、**新しい出会い**

**年表の見方**
曲・アーティストの詳細の「年表」と、分析タブの「あなたの音楽年表」は、上のボタンで表示する種類を選べます。「すべて」で全部、種類のボタンを押すとその種類だけ（複数選べます）になります。

**わからない指標があったら**
見出しの横の「**？**」を押すと、その指標の説明が出ます。

**いちばん上に戻る**
画面を下にスクロールすると、右下に「↑」ボタンが出ます。詳細画面や説明書の中でも使えます。

**ランキングの順位の決め方**
再生回数の多い順です。回数が同じ曲（アーティスト）は**同じ順位**になり、次の順位はその数だけ飛びます（例：1位、2位、2位、4位）。同じ順位の中では、最近聴いたものが上に表示されます。

## 正常に動いているかの確かめ方

専用ページの **「記録の状態」**（スマホではいちばん下、PCでは右側）を見てください。

| 項目 | 正常なとき |
|---|---|
| 最終確認 | 1時間以内の日時になっている（緑の点がついている） |
| 次の確認 | 最終確認の約1時間後の日時（GitHubの都合で少し遅れることがあり、そのときは「少し遅れています」と出る） |
| 最後に聴いた曲 | 最後に記録された曲とアーティスト・聴いた時刻（押すと曲の詳細が開く。聴いていなければ古いままで正常） |
| 連携の期限 | 日付と「あと○日」が出ている |

その下の **「最終確認で更新した内容」** には、最終確認の時刻の自動実行（1時間ごと）で何が更新されたかが出ます。

日時はすべて「2026/10/15（木）23:49」のように日付つきで表示します。ページを開いたまま30分以上たってから戻ってきたとき（または1時間以上開いたまま操作していないとき）は、自動で最新の記録に読み込み直します。

| 項目 | 意味 |
|---|---|
| 新しい再生 | 新しく記録した再生の数（聴いていなければ0件で正常） |
| 曲情報の補完 | ジャケ写などが欠けていた最近の曲を調べ直した数（ふだんは0件） |
| アーティスト写真 | 新しく取得したアーティスト写真の数と、残りの数 |
| 過去曲のジャケ写 | 取り込んだ過去の履歴の曲で、新しくジャケ写が付いた数と、残りの数 |
| 問い合わせ | Spotifyに問い合わせた回数と、直近24時間の合計（590回まで）。Spotifyの制限で休んでいるときは「休憩中」と再開の時刻 |

**何か問題が起きると、ページの上部に色のついたお知らせが出ます。** あわせて、GitHubから「Run failed」という件名のメールが届きます。
お知らせには原因と直し方が書いてあり、「詳しい手順を見る」を押すと、この説明書の該当する項目が開きます。

## 止まったときの直し方

ページ上部のお知らせの **見出し** を見て、下の該当する項目の手順を行ってください。どれもスマホだけでできます。

| お知らせの見出し | 原因 | やること |
|---|---|---|
| ようこそ！あと少しで記録が始まります | はじめての設定が途中 | [はじめての設定](#はじめての設定スマホだけでok) の続き |
| Spotifyとの連携が切れています | 連携の期限切れ（いちばん多い） | [A. 連携のやり直し](#a-連携のやり直しいちばんよくある直し方) |
| Spotifyとの連携の期限が近づいています | もうすぐ期限切れ | [A. 連携のやり直し](#a-連携のやり直しいちばんよくある直し方) |
| Spotifyのアプリ情報が正しくありません | Client ID／Secretの不一致 | [B](#b-spotifyのアプリ情報が正しくありません) |
| Spotifyにアクセスを拒否されました | Premium切れなど | [C](#c-spotifyにアクセスを拒否されました) |
| Spotifyに接続できない状態が続いています | Spotify側の一時的な不具合 | [D](#d-spotifyに接続できない状態が続いています) |
| 自動の確認が止まっているようです | GitHubの自動実行が止まった | [E](#e-自動の確認が止まっているようです) |
| （ページ自体が開かない・404） | ページの公開設定 | [F](#f-ページが開かない404と出る) |

### A. 連携のやり直し（いちばんよくある直し方）

Spotifyとの連携をやり直します。**スマホで3分ほど**で終わります。

1. 専用ページのお知らせの「**Spotifyと連携する**」を押す（または「記録の状態」→「説明書・ダウンロード」→「Spotifyと連携し直す」）
2. Client ID と Client Secret を入力して「**Spotifyと連携する**」→「**同意する**」
   - Client ID と Client Secret は、[Spotify for Developers](https://developer.spotify.com/dashboard) で作ったアプリの「Settings」にあります
3. 表示されたトークンを「トークンをコピー」→「**GitHubで上書きする**」→ 入力欄に貼り付けて「**Update secret**」
4. 完了です。1時間以内に自動で記録が再開します
   - すぐ確かめたいときは、GitHubの「Actions」→「Spotify再生記録」→「Run workflow」を押し、緑のチェック ✅ になればOKです

> 止まっていた間の再生も、**直近50曲分まではさかのぼって記録されます**。それより前の分は記録されないので、お知らせが出たら早めに直すのがおすすめです。

連携ページで「Redirect URI が登録されていない」と出たときは、連携ページの手順1のURLを、Spotifyのアプリの「Redirect URIs」に登録してください。

### B. Spotifyのアプリ情報が正しくありません

GitHubに登録した Client ID か Client Secret が間違っています。

1. [Spotify for Developers](https://developer.spotify.com/dashboard) → 作ったアプリ →「Settings」を開く
2. GitHubのこのリポジトリで「Settings」→「Secrets and variables」→「Actions」を開く
3. `SPOTIFY_CLIENT_ID` の鉛筆アイコン → Spotifyの画面の Client ID を**コピーボタンで**コピーして貼り付け →「Update secret」
4. `SPOTIFY_CLIENT_SECRET` も同じように（Spotifyの「View client secret」から）
5. 「Actions」→「Run workflow」で確認

Spotifyの画面で Client Secret を作り直した（「Rotate」を押した）場合もこの手順です。

### C. Spotifyにアクセスを拒否されました

1. **Spotify Premium の契約が続いているか**確認してください。このしくみはPremiumでないと動きません（再加入すれば自動で戻ります）
2. [Spotify for Developers](https://developer.spotify.com/dashboard) → 作ったアプリ →「User Management」に、自分の名前とSpotifyのメールアドレスが登録されているか確認し、なければ追加
3. それでも直らなければ、[A. 連携のやり直し](#a-連携のやり直しいちばんよくある直し方) を行う

### D. Spotifyに接続できない状態が続いています

Spotify側の一時的な不具合のことがほとんどで、**何もしなくても自動で直ります**。
1日以上続くときは、[A. 連携のやり直し](#a-連携のやり直しいちばんよくある直し方) を試してください。

### E. 自動の確認が止まっているようです

GitHubの自動実行が止まっている状態です。GitHubは、60日間まったく更新のないリポジトリの自動実行を止めることがあります。

1. このリポジトリの **「Actions」** タブを開く
2. 画面上部に黄色い帯と **「Enable workflow」** ボタンがあれば押す
3. 左の「Spotify再生記録」→「Run workflow」を押し、緑のチェック ✅ になるか確認
4. 赤い ❌ になった場合は、その行を押して「record」→ 赤くなっている段階を開き、表示されたメッセージを確認

### F. ページが開かない（404と出る）

1. このリポジトリの「Settings」→ 左メニュー「Pages」を開く
2. 「Source」が **GitHub Actions** になっているか確認し、違えば変更
3. リポジトリ名の横が **Public** になっているか確認（Privateだと無料プランではページを公開できません）
4. 「Actions」→「Run workflow」で、「record」と「deploy」が緑のチェックになるか確認

### それでも直らないとき

Claudeなどに相談するときは、次の3つのスクリーンショットを見せると原因がすぐわかります。
**Client Secret やトークンが写っていないか、必ず確認してから送ってください。**

1. 専用ページの上部のお知らせと、下の「記録の状態」
2. GitHubの「Actions」の一覧画面
3. 失敗した実行 →「record」→「再生履歴を取得」を開いた画面

## 半年に一度やること

Spotifyの決まりで、連携は **発行から約180日で期限切れ** になります。

- 期限の目安は、専用ページの「記録の状態」→「連携の期限」に表示されます
- **期限の2週間前から、ページ上部にお知らせが出ます**
- お知らせが出たら、[A. 連携のやり直し](#a-連携のやり直しいちばんよくある直し方) を行ってください（期限前にやれば、記録は途切れません）

## 過去の再生履歴を取り込む

自動の記録は、設定した日以降の分だけです。それより前の分は、Spotifyに再生履歴を請求して取り込めます。**スマホだけでできます。**

設定した日以降の分も、取り込むと役に立ちます。連携が切れて記録が止まっていた期間や、Spotifyの自動記録から漏れた再生が、取り寄せた履歴で埋まります。

**1. Spotifyに請求する**
1. ブラウザで [Spotifyのプライバシー設定](https://www.spotify.com/account/privacy/) を開いてログイン
2. 「データをダウンロード」で、次のどちらか（または両方）にチェックして請求
   - **拡張ストリーミング履歴**：アカウントを作ってからの**全期間**。届くまで最大30日。おすすめ
   - **アカウントデータ**：**直近1年分**。届くまで約5日
3. 登録メールアドレスに確認のメールが届くので、確認する

**2. 届いたら取り込む**
1. 届いたメールのリンクから **my_spotify_data.zip** をダウンロード
2. 専用ページの「記録の状態」→「説明書・ダウンロード」→「**過去の再生履歴を取り込む**」を開く
3. 「ファイルを選ぶ」で my_spotify_data.zip を選ぶ → 内容を確認して「**履歴ファイルを保存する**」（`history-20261015.csv` のような、日付つきの名前で保存されます）
4. 「**GitHubのアップロード画面を開く**」→「choose your files」で、いま保存したファイルを選ぶ →「**Commit changes**」

1時間以内（または「Run workflow」を押した直後）に、専用ページの「全期間」などに過去の分が加わります。

**知っておくこと**
- 数え方は自動記録と同じで、**30秒以上再生した曲を1回**としています。ポッドキャスト・動画・プライベートセッション中の再生は含みません
- 前に取り込んだ履歴は上書きされず、別のファイルとして加わります。自動記録や、前に取り込んだ履歴と重なる部分は、二重に数えないよう自動で調整しています
- シングルとアルバムなどで同じ曲が別々に登録されている場合は、**曲名とアーティストが同じなら1曲にまとめて**数えています
- 取り寄せたデータに入っているIPアドレスや端末名などは、取り込みません
- 過去の曲のジャケ写や、featで参加しているアーティストの情報は、Spotifyに問い合わせて埋めています。**アーティスト写真を先に**、ジャケ写はそのあとに調べます。どちらも**よく聴いた順、同じ回数なら最近聴いた順**に埋まり、それまでは頭文字のアイコンで表示されます
- 問い合わせを節約するため、次の工夫をしています
  - 同じアルバムの別の曲でジャケ写が分かっている曲は、問い合わせずにそのジャケ写を使う（featのアーティストや曲の長さは、ジャケ写が全部そろったあとに仕上げる）
  - 同じアルバムにまだの曲が3曲以上あるときは、アルバムごと1回で調べる
  - シングル版・アルバム版などで、別の番号にもうジャケ写がある曲は調べない
- Spotifyへの問い合わせは**24時間で600回まで**という制限があるため（実際の記録から確認）、**1時間に25回・1日に590回まで**に抑えて、24時間均等に使っています。数千曲あると全部そろうまで2〜3週間かかりますが、何もしなくても自動で進みます
- 新しく聴き始めたアーティストの写真は、いちばん優先して調べるので、ふつうは1時間以内に付きます（新しく聴いた曲のジャケ写は、再生の記録と一緒に届くので待ち時間はありません）
- 進み具合は、GitHubの「Actions」→ 最新の「Spotify再生記録」→「record」→「再生履歴を取得」で、「今回の問い合わせ枠」「残り 約○曲」の行を見ると分かります
- 「アカウントデータ」で取り込んだ分は、曲を特定する番号が入っていないため、ジャケ写が付かないことがあります。あとから「拡張ストリーミング履歴」が届いたら、同じ手順で追加してください（重なる期間は「拡張ストリーミング履歴」の方が使われます）
- 万一Spotifyから「問い合わせが多すぎる」と言われたときは、Spotifyに指定された時間（最低30分）だけ画像の補完を休んでから自動で再開します。そのあいだも再生の記録は続きます

## 集計から外したい再生があるとき

聴いた覚えのない曲が大量に記録されているなど、集計に入れたくない再生がある場合は、`data/exclude.json` に一覧として書いておくと、**ランキングや記録などの集計と、ダウンロードのCSVから外せます**。元の記録は消さないので、一覧から外せばいつでも元に戻せます。

書き方がわからないときは、ダウンロードした再生記録（CSV）と、外したい日付・曲名をClaudeなどに伝えて作ってもらい、GitHubの `data` フォルダにアップロードしてください。

```
{
 "groups": [
  {
   "name": "外す理由（自由に）",
   "plays": [["2025-08-26T23:31:09Z", "曲のID"], ...]
  }
 ]
}
```

## ファイルのダウンロード

専用ページの「記録の状態」にある **「説明書・ダウンロード」** を押して開くと、次の3つをいつでも取得できます。手元にファイルを残しておく必要はありません。

| ファイル | 中身 | 使うとき |
|---|---|---|
| **更新用ファイル（v21 など）** | `README.md` と `scripts` の中身だけ | このツールを最新版にするとき（下の「最新版にする手順」） |
| **友だちに渡すキット（zip）** | この説明書・プログラム一式（あなたの再生記録は入っていません） | 新しく作り直すとき、友だちに渡すとき |
| **再生記録（CSV）** | これまでに記録したすべての再生（日時・曲名・アーティストなど） | Excelで自分で集計したいとき、バックアップしたいとき |

zipは、GitHubに置いてある最新のプログラムから1時間ごとに自動で作り直しています。パスワードやトークンなどの秘密の情報は入っていません。

あなたの再生記録も含めて丸ごと保存したいときは、GitHubのリポジトリ画面で緑の「**Code**」→「**Download ZIP**」を押してください。

**最新版にする手順**（新しいバージョンのファイルを受け取ったとき）
1. 更新用ファイルを解凍する
2. GitHubのリポジトリのトップで「Add file」→「Upload files」→ `README.md` を選んで「Commit changes」
3. `scripts` フォルダを開いてから「Add file」→「Upload files」→ `scripts` の中のファイルを全部選んで「Commit changes」
4. 「Actions」→「Spotify再生記録」→「Run workflow」

## パソコンで連携する方法（予備）

ふだんは専用ページの連携ページ（スマホでOK）を使ってください。連携ページでどうしてもうまくいかないときだけ、パソコン（Mac・Windowsどちらでも）でこの方法を使います。

1. Spotifyのアプリの「Redirect URIs」に `http://127.0.0.1:8888/callback` を追加して保存
2. パソコンに [Python](https://www.python.org/downloads/) が入っていなければ入れる（Windowsはインストール時に「Add python.exe to PATH」にチェック）
3. 専用ページの「友だちに渡すキット（zip）」をダウンロードして解凍
4. 解凍したフォルダで、次を実行
   - Mac：「ターミナル」を開き、`cd ` のあとにフォルダをドラッグして Enter → `python3 scripts/auth.py`
   - Windows：フォルダを開き、上のアドレス欄に `cmd` と入力して Enter → `py scripts\auth.py`
5. 画面の指示どおりに Client ID・Client Secret・リポジトリ名（例：`yourname/listening-log`）を入力 → ブラウザで「同意する」
6. 表示（またはコピー）されたトークンを、GitHubの `SPOTIFY_REFRESH_TOKEN` に貼り付けて「Update secret」

## 友だちに渡すとき

このリポジトリを「テンプレート」にしておくと、友だちはボタン1つで自分用のコピーを作れます。友だちの記録とあなたの記録が混ざることはありません。

1. リポジトリの「**Settings**」→「General」のいちばん上にある **「Template repository」にチェック**
2. リポジトリのURL（例：`https://github.com/yourname/listening-log`）を友だちに送る
3. 友だちは [はじめての設定](#はじめての設定スマホだけでok) の手順で進めます

あなた自身の再生記録（`data` フォルダ）を友だちのコピーに含めたくない場合は、配布用に別のリポジトリを作り、「友だちに渡すキット（zip）」の中身だけを入れたものをテンプレートにしてください。

## しくみの全体像

```
 Spotify ──(1時間ごとに再生履歴を確認)──▶ GitHub Actions
                                            │
                                            ├─ data/ に記録を追加して保存（これだけ記録に残します）
                                            └─ docs/（専用ページ・ダウンロード）を作り直し、
                                               その場でGitHub Pagesにお届け（記録には残しません）
                                                      │
                                   GitHub Pages で公開 ▼
                                         スマホ・PCで見る
```

専用ページ本体（`docs`フォルダ）は、毎時まるごと作り直す大きなファイルです。これを毎回記録に残すとGitHubの保存容量をどんどん使ってしまうため、**「記録する」のは`data`フォルダ（実際の再生記録）だけ**にし、専用ページは「作って、その場で公開して、記録には残さない」方式にしています。

### ファイルの説明

| 場所 | 中身 | さわっていいか |
|---|---|---|
| `data/plays.csv` | 自動で記録した再生 | ❌ 消さない（消すと記録がなくなります） |
| `data/history-日付.csv` | Spotifyから取り寄せた過去の再生履歴（取り込むたびに1つ増える） | ❌（取り込みページで作ってアップロード） |
| `data/exclude.json` | 集計から外す再生の一覧（あれば） | 外したい再生があるときだけ |
| `data/tracks.json` | 過去の履歴の曲のジャケ写・参加アーティストの情報 | ❌ |
| `data/artists.json` | アーティスト写真の情報 | ❌ |
| `data/status.json` | 最後に確認した時刻・エラーの内容 | ❌ |
| `docs/` | 専用ページとダウンロード用ファイル（毎回作り直すだけで、GitHubの記録には残しません） | ❌ |
| `.gitignore` | `docs/` を記録に残さないための設定 | 改造するときだけ |
| `scripts/fetch.py` | Spotifyから再生履歴を取ってくる | 改造するときだけ |
| `scripts/build_report.py` | 専用ページを作る | 改造するときだけ |
| `scripts/template.html` | 専用ページのデザイン | 改造するときだけ |
| `scripts/setup.html` | Spotifyとの連携ページ | 改造するときだけ |
| `scripts/import.html` | 過去の再生履歴の取り込みページ | 改造するときだけ |
| `scripts/page-common.css` | 連携ページ・取り込みページのデザイン | 改造するときだけ |
| `scripts/auth.py` | パソコンで連携する予備の方法 | 連携ページが使えないときだけ |
| `scripts/import_history.py` | パソコンで履歴を変換する予備の方法 | 取り込みページが使えないときだけ |
| `.github/workflows/spotify.yml` | 1時間ごとに動かす設定 | 改造するときだけ |

## 大事な注意

- **Client Secret とリフレッシュトークンは、人に見せたり送ったりしないでください。** スクリーンショットを撮るときは写らないように注意してください
- 連携ページに入力した Client ID・Client Secret は、そのブラウザとSpotifyのあいだでだけ使われ、どこにも保存されません。人のスマホや共用のパソコンでは連携しないでください
- `data` フォルダは記録そのものなので、消したり編集したりしないでください
- このリポジトリと専用ページは公開（Public）です。**曲名・アーティスト名・再生日時は誰でも見られる状態**になります（URLを知らない人がたどり着くことはまずありません）。Spotifyのログイン情報などは公開されていません（GitHubのSecretに保管されています）
- Spotify Premium を解約すると記録が止まります（再加入で自動再開）
